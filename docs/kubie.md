# Kubie и окружения Kubernetes

Kubie открывает отдельную сессию с временным kubeconfig. Окружение определяется локально по исходному файлу подключения. Имя контекста может быть произвольным, например `k3s-dev`, `cluster-42` или имя, выданное облачным провайдером. Переименование для цветовой индикации не требуется.

## Установка

Нужны Kubie, Starship, GNU Stow и uv. На macOS Kubie устанавливается через Homebrew; на Linux используйте проверенный бинарник из официального релиза. Затем из корня репозитория:

```sh
sh scripts/install.sh --check
sh scripts/install.sh --migrate
sh scripts/setup-kube-environment.sh
mkdir -p ~/.kube ~/.config/terminal-dotfiles
cp -n examples/kubie.yaml.example ~/.kube/kubie.yaml
cp -n examples/kube-environments.yaml.example ~/.config/terminal-dotfiles/kube-environments.yaml
```

Существующие локальные настройки сохраните и дополните вручную. Bash использует тот же установленный helper; дополнительно выполните `sh scripts/install-bash.sh`. Откройте новую вкладку и новую сессию Kubie. Runtime создаётся через `uv venv` и содержит PyYAML 6.0.3. Сеть нужна при установке зависимости; вычисление окружения работает без сети. Без установленного runtime Kubernetes-индикатор скрыт.

## Структура каталогов

По умолчанию корень — `~/.kube/configs`. Поддерживаются следующие структуры относительно корня:

| Категория | Структура |
| --- | --- |
| Лаборатория | `lab/<env>/<file>.yaml` |
| Локальный кластер | `local/<env>/<file>.yaml` |
| Компания | `corp/<company>/<env>/<file>.yaml` |
| Облако | `public/<provider>/<account>/<env>/<file>.yaml` |

Расширение `.yml` также поддерживается образцом Kubie. Уровень `<env>` фиксирован структурой; совпадения в имени компании, кластера или контекста не учитываются. Пути симлинков приводятся к реальным путям. При переносе kubeconfig сохраните работоспособность относительных ссылок на сертификаты и ключи.

Имена контекстов должны быть уникальны во всех включённых файлах. Проверяйте их через `kubie lint`. `~/.kube/config` не включён в образец, чтобы совместимые копии не создавали дубликаты. Резервные копии храните вне сканируемого дерева; kubeconfig и приватный справочник не добавляйте в Git.

## Справочник и исключения

Настройки находятся в `~/.config/terminal-dotfiles/kube-environments.yaml`. Образец содержит DEV, TEST, PROD, UAT и NT. Поле `environments` при наличии заменяет стандартный справочник целиком. Новое окружение добавляется записью с `label` и `color`; изменение кода не требуется. Подпись содержит от 1 до 12 символов `A-Z`, цифр, `?`, `_`, `-`. Цвет задаётся шестью шестнадцатеричными цифрами, допускается начальный `#`.

`directory_aliases` задаёт явные синонимы каталогов, например `production: prod`. UAT и NT остаются самостоятельными окружениями.

Точное исключение имеет приоритет над каталогом:

```yaml
overrides:
  - source: corp/company/shared.yaml
    context: cluster-42
    environment: uat
```

`source` — точный реальный путь относительно корня; для внешнего файла задайте абсолютный путь. Исключения позволяют использовать один файл с контекстами разных окружений. Несколько совпадающих исключений считаются ошибкой, даже если их значения одинаковы.

Порядок определения: точное исключение → каталог → `?ENV`. Суффиксы и префиксы имени контекста не используются. Неизвестное окружение, дубликат контекста, повреждённая конфигурация или несовпадение активного подключения с исходным дают `?ENV`.

Helper учитывает `configs.include` и `configs.exclude` из `~/.kube/kubie.yaml`; без файла используются стандартные шаблоны Kubie. Проверка подключения сравнивает cluster и user активного и исходного kubeconfig, игнорируя изменяемый namespace. Переписанные сторонним инструментом параметры подключения требуют повторного входа в Kubie. Файлы перечитываются при отображении, поэтому изменения справочника и перемещения не требуют сброса кэша. Для очень большого числа kubeconfig стоимость сканирования следует измерить отдельно.

## Отображение и диагностика

Starship и Kitty используют один resolver. Окружение выделено цветной плашкой, за ней идут контекст и namespace через ` / `. Короткую подпись можно задать для точного имени контекста в локальном `~/.config/terminal-dotfiles/kube-environments.yaml`:

```yaml
context_labels:
  'prod:example': core01
```

В этом примере вкладка выглядит как `3 PROD core01 / app`, а prompt показывает `[PROD] core01 / app`. Для контекста без подписи отображается полное имя. Выбирайте разные подписи для разных контекстов. `kubie info ctx` и поле `context` в диагностике показывают исходное имя.

При смене namespace окружение сохраняется; `exit` скрывает Kubernetes-индикатор. Контекст каждой вкладки независим. Параметры `--context`, `--kubeconfig` и `-n` отдельной команды могут переопределять выбор сессии.

Внутри сессии:

```sh
~/.config/terminal-dotfiles/kube-environment --json
```

Диагностика показывает окружение, источник и причину решения, без credentials и адреса API. `ambiguous-source` означает дубликат, `connection-mismatch` — несовпадение подключения, `conflicting-overrides` — несколько исключений. Для неизвестного каталога проверьте структуру и справочник.

При собственном `STARSHIP_CONFIG` перенесите секцию `[custom.kube_environment]` и `${custom.kube_environment}` в формат prompt. Старые правила `[kubernetes.contexts]` больше не нужны.

Проверяйте две параллельные сессии, смену namespace, выход и повторный вход. Локальные тесты используют временные kubeconfig и не обращаются к кластеру. Документация: [Kubie](https://github.com/kubie-org/kubie), [Starship custom modules](https://starship.rs/config/#custom-commands).
