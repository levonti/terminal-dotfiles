# Вкладки Kitty

Общий конфиг использует встроенный стиль `fade` с `tab_fade 1`: одна ячейка по краям полностью совпадает с фоном панели. Получаются плоские вкладки с зазором, без градиента и вертикальных разделителей. Активная вкладка выделена бирюзовым фоном и жирным текстом; остальные сохраняют светлый текст на тёмном фоне.

Номер перед названием соответствует переходу по `Command+1…9` на macOS или `Super+1…9` на Linux. `Command/Super+P` открывает список вкладок. Для абсолютного пути или пути с `~/` показывается имя последнего каталога; домашний и корневой пути сохраняются как `~` и `/`.

Локальная вкладка показывает каталог: например, `project`. При запуске программы он сохраняется: `project htop`. Между каталогом и программой используется обычный пробел, без декоративного разделителя. Показывается имя исполняемого файла, без аргументов команды. SSH-вкладка сохраняет хост и последний сообщённый удалённый каталог: `host:project htop`; после завершения команды возвращается `host:project`. Префикс `root@host` сохраняется. Активная и неактивная вкладки используют одну подпись. Длинные подписи ограничены 40 ячейками; в стиле `custom` при сокращении сохраняется место для имени команды, если вкладке доступно хотя бы 12 ячеек текста. В более тесной панели используйте список вкладок. Автоматическая подпись вкладки не меняет заголовок самого окна.

Если две оболочки открыты в одном каталоге, задайте им имена по назначению через `Command/Super+Shift+T`, например `infra` и `deploy`. Назначенное имя сохраняется при смене каталога и имеет приоритет над автоматическим заголовком и Kubie; двоеточия и пробелы в нём не сокращаются. Чтобы вернуть автоматическое название, откройте переименование и отправьте пустую строку. Общий конфиг не назначает имена пользовательским сессиям автоматически.

В локальной сессии Kubie общий Bash/Zsh получает контекст через `starship module kubernetes`: это тот же модуль и конфиг, что используются в prompt, включая `STARSHIP_CONFIG`. Примеры: `[☸ DEV example::app]`, `[☸ example::app]`, `[☸ ? ENV default::app]`. У production нет текстовой метки окружения: красным выделяется только значок `☸`. Значок dev зелёный, test — жёлтый, неизвестного окружения — фиолетовый; остальной текст использует обычный цвет. В Kitty оттенок значка адаптируется к фону активной вкладки для контраста не ниже 3:1. Каталог и команда дополняют контекст: `[☸ example::app] project htop`. Starship читает локальный kubeconfig без обращения к API кластера. Если Starship или его Kubernetes-модуль отключён, отдельный формат для вкладки не придумывается.

Локальная оболочка передаёт единый снимок состояния: PID, каталог, контекст, ожидание ввода либо запуск программы. В Kitty проверяется принадлежность PID той же PTY-сессии; окружение другого процесса переднего плана для этого не используется. Поэтому ожидающий родительский `kubie` не отображается как работающая команда. После выхода PID перестаёт существовать, и контекст скрывается даже при возврате в старую оболочку без новых hooks. Обычный prompt также очищает контекст. Zsh сообщает запуск через `preexec`, Bash 4.4+ — через локальный `PS0`; Bash 3.2 использует сведения о foreground-программе. При переходе в SSH локальные метаданные не используются и новые hooks не загружаются на сервер. Это контекст сессии: параметры `--context`, `--kubeconfig` и `-n` отдельной команды его не меняют. Для работающих оболочек перечитайте соответствующий `.zshrc` / `.bashrc` или откройте новую вкладку; уже открытая сессия Kubie также должна загрузить обновлённый конфиг.

Реальный локальный цикл закреплён в `tests/test_kubie_cycle.py`: установленные Kubie, Starship и htop запускаются в PTY с временным HOME и отдельным kubeconfig. Проверяются `kubie ctx`, работа и закрытие htop, смена namespace, `exit` и повторный вход. Валидация namespace по API отключена, запуск kubectl блокируется тестом; личные контексты и удалённые хосты не затрагиваются. Тест не заменяет визуальную проверку окна Kitty.

Обычный SSH не сообщает клиенту о выполнении команд автоматически. Удалённые конфиги и окружение не изменяются; автоматическая установка или загрузка серверных hooks не используется. Kitty обрабатывает только уже переданные сервером или TUI заголовки и OSC 7. Переданный ранее удалённый каталог сохраняется, когда программа заменяет заголовок своим именем. Локальный каталог SSH-клиента вместо удалённого не показывается. Если SSH-сеанс не сообщает имя программы, оно не выводится: клиент не может достоверно определить его из зашифрованного соединения.

Общая функция `draw_title` в `tab_bar.py` используется как стилем `fade`, так и сетевой панелью `custom`. Оба файла должны быть установлены через Stow. В `custom` распределение ширины не зависит от активной вкладки: её переключение меняет цвет и жирность без перемещения соседних вкладок. При недостатке места подписи сокращаются равномерно, с сохранением приоритета `root@`; сетевой блок уступает место вкладкам. Контраст заданных цветов текста и фона: 8.61:1 для активной вкладки и 7.88:1 для неактивной. Новое поведение проверяется автоматически; прежняя визуальная проверка Kitty 0.49.0 не подтверждает новый вид на всех устройствах.

Для альтернативного стиля добавьте в `~/.config/kitty/kitty.local.conf`:

```conf
# Закруглённый Powerline
tab_bar_style powerline
tab_powerline_style round
```

Или для тонких разделителей:

```conf
tab_bar_style separator
tab_separator " │ "
```

Мягкий fade с несколькими ячейками по краям также возможен:

```conf
tab_bar_style fade
tab_fade 0.15 0.35 0.7 1
```

Удалите эти строки, чтобы вернуться к общему стилю. Перезагрузите настройки сочетанием `Ctrl+Command+,` на macOS или `Ctrl+Shift+F5` на Linux; SSH-сессии продолжаются.
