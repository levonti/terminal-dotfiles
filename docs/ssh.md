# SSH из Kitty

Общий `.zshrc` подключает `~/.config/terminal-dotfiles/ssh.zsh`. Функция действует только для интерактивного `ssh` внутри Kitty. Скрипты, `scp`, `sftp`, Git по SSH и другие терминалы используют обычный OpenSSH. Запросы `ssh -G`, `ssh -V`, `ssh -Q` и режимы `-T`, `-N`, `-W`, `-O` также проходят напрямую.

## Как выбирается режим

| Хост | Команда | Результат |
| --- | --- | --- |
| Не совпал с разрешающей маской или исключён | `ssh ...` с `TERM=xterm-256color` | Совместимый terminfo; серверные файлы не меняются |
| Совпал с разрешающей маской | `kitten ssh ...` | Kitty переносит terminfo и настраивает интеграцию в домашнем каталоге удалённого пользователя |

Для управляемых хостов `kitten ssh` также задаёт `force_color_prompt=yes` на время сеанса. Стандартный Ubuntu Bash иначе оставляет prompt бесцветным при `TERM=xterm-kitty`. Эта переменная не устанавливает Starship и не правит удалённый `.bashrc`.

Приватный файл правил: `~/.config/terminal-dotfiles/managed-ssh-hosts`. Отсутствующий или пустой файл означает совместимый режим для всех хостов. Правила похожи на `.gitignore`, но работают с именем хоста, а не с путём:

- Одна маска на строку; пустые строки и строки с `#` в начале игнорируются.
- `*` означает любое число символов, включая точки; `?` — один символ. Маски сравниваются со всем именем целиком, без учёта регистра.
- `!` в начале строки исключает хост. Если совпало несколько строк, действует **последняя**. Повторная разрешающая маска после исключения снова включает хост.
- Маски вида `10.20.*` работают для IP-адресов, указанных как `HostName` или непосредственно в команде SSH. CIDR (`10.20.0.0/16`), классы `[]`, `**` как отдельный оператор и экранирование Gitignore здесь не поддерживаются.

```gitignore
# Устройства в этом домене
*.example.internal
# Сервер, который должен оставаться в совместимом режиме
!db01.example.internal
# Подключения по адресу из этой подсети
192.0.2.*
```

Функция сверяет маски с **конечным `HostName`**, полученным через `ssh -G`: SSH-алиас и указанный в нём `HostName` дают один результат. Функция не делает отдельный DNS-запрос для поиска IP-адреса: маска IP не сработает для имени, которое позднее разрешится в этот адрес. OpenSSH может канонизировать имя по своему конфигу, но смена адреса в DNS сама по себе не переключает режим. SSH host key по-прежнему проверяется OpenSSH.

**Добавление широкой маски заранее разрешает `kitten ssh` и для новых хостов, которые под неё попадут.** Маски и исключения хранятся только в приватном файле, не в публичном репозитории. Для одинаковой политики на Mac и Linux синхронизируйте этот файл отдельно, например через закрытый репозиторий.

## Когда добавлять маску

1. Вы разрешаете изменения в домашнем каталоге всех удалённых пользователей и хостов, которые охватывает маска: `kitten ssh` может сохранять там terminfo и файлы интеграции.
2. Этим хостам нужен полный режим Kitty. Для программ через `sudo` terminfo также должен быть доступен привилегированному пользователю, например через системный пакет `kitty-terminfo`.
3. Если нужен одинаковый prompt, Starship и общий `starship.toml` уже установлены и подключены к оболочке на этих хостах. Сам по себе terminfo prompt не меняет.

Пока изменения на серверах не разрешены, оставьте файл правил пустым или не создавайте его. Проверка `infocmp xterm-kitty` показывает наличие terminfo, но не даёт разрешения на `kitten ssh`.

## Использование и обход

После добавления нового файла из пакета `zsh` на уже настроенном устройстве один раз повторите из корня репозитория:

```sh
stow --no-folding --simulate --verbose --target="$HOME" zsh
stow --no-folding --target="$HOME" zsh
```

Затем откройте новую вкладку Kitty. `ssh my-alias` выберет режим по приватным правилам. Для разового обычного OpenSSH вызовите `command ssh my-alias`; для разового полного режима на разрешённом хосте — `kitten ssh my-alias` (если `kitten` доступен в `PATH`) или полный путь к `kitten`. Вне Kitty функция передаёт вызов обычному `ssh`.

Для диагностики на удалённом хосте: `printf '%s\n' "$TERM"`, `infocmp "$TERM"` и `tput colors`. Сообщение об отсутствии `editor` проверяйте отдельно: PowerDNS использует переменную `EDITOR`, а при её отсутствии запускает `editor`. Настройка `TERM` не устанавливает Starship и не определяет редактор.
