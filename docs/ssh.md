# Совместимый SSH на macOS и Linux

Обычная команда `ssh` в интерактивных Zsh и Bash автоматически запускает OpenSSH с `TERM=xterm-256color` для **всех** хостов. В Zsh функция загружается из `~/.config/terminal-dotfiles/ssh.zsh`, в Bash она определена в общем `~/.bashrc`. Политика действует и в Kitty, и в других терминалах, независимо от домена или IP-адреса.

Локальный `TERM` не меняется: значение задаётся только дочернему процессу SSH. Аргументы, стандартные потоки и код завершения передаются обычному OpenSSH. `ssh -G`, пробросы портов и удалённые команды работают с теми же параметрами. При отсутствии удалённого PTY значение `TERM` не передаётся как тип терминала.

## Обычные и последовательные подключения

```sh
ssh gateway.example.internal
# На промежуточном хосте:
ssh user@192.0.2.31
```

Первое интерактивное подключение получает `xterm-256color`. Обычный SSH на промежуточном хосте передаёт его конечному устройству: установка наших dotfiles на промежуточном хосте для этого не нужна. Это действует при условии, что конфигурация оболочки, tmux/screen или другая SSH-обёртка на промежуточном хосте не заменяет `TERM`.

`ssh user@host`, SSH-алиасы и `ssh -J gateway target` используют ту же политику. Маршруты и алиасы в SSH-конфиг автоматически не добавляются.

## Применение обновления

На настроенном устройстве выполните `git pull --ff-only` в клоне и откройте новую вкладку терминала. Повторный Stow не нужен: изменились только существующие файлы. В уже открытом Zsh достаточно:

```sh
source ~/.config/terminal-dotfiles/ssh.zsh
```

В уже открытом Bash выполните `source ~/.bashrc` или запустите новый `bash`. Для Bash с `--login` существующий `~/.bash_profile` должен подключать `~/.bashrc`, как описано в README.

## Что меняется относительно прежней политики

- `managed-ssh-hosts` больше не читается. Приватный файл можно сохранить; маска не включает полный режим.
- Обычный `ssh` больше не запускает `kitten ssh` и не переносит terminfo или интеграцию оболочки на сервер.
- `scp`, `sftp`, Git по SSH и неинтерактивные скрипты используют обычные исполняемые файлы; интерактивная функция `ssh` на них не распространяется.
- Ранее установленный terminfo и файлы интеграции на серверах не удаляются.

Приложения на удалённом хосте определяют возможности терминала по `xterm-256color`; некоторые расширения Kitty могут не определяться автоматически. Шрифт, тема и локальные сочетания клавиш Kitty остаются доступны. Общий Starship и zoxide на каждом устройстве по-прежнему требуют отдельной установки.

## Проверка и явный обход

На каждом шаге интерактивного подключения проверьте:

```sh
printf '%s\n' "$TERM"
infocmp "$TERM" >/dev/null && tput colors
```

Ожидается `xterm-256color` и `256`. Если приложение запускается от другого пользователя, например через `sudo`, описание терминала должно быть доступно и ему.

Для явного обхода функции используйте `command ssh host`: он передаст текущий локальный `TERM`. `kitten ssh host` остаётся отдельной командой для разового полного режима на хосте, где разрешены изменения в домашнем каталоге удалённого пользователя.

Ошибки доступа macOS к SDK из `Downloads` и отсутствие серверного редактора проверяются отдельно. Настройка `TERM` не меняет права доступа, не устанавливает редактор и не правит конфигурацию удалённой оболочки.
