# SSH из Kitty

Общий `.zshrc` подключает `~/.config/terminal-dotfiles/ssh.zsh`. Функция действует только для интерактивного `ssh` внутри Kitty. Скрипты, `scp`, `sftp`, Git по SSH и другие терминалы используют обычный OpenSSH. Запросы `ssh -G`, `ssh -V`, `ssh -Q` и режимы `-T`, `-N`, `-W`, `-O` также проходят напрямую.

## Как выбирается режим

| Назначение | Команда | Результат |
| --- | --- | --- |
| Неизвестное или не внесённое в список | `ssh ...` с `TERM=xterm-256color` | Совместимый terminfo; серверные файлы не меняются |
| Явно управляемое | `kitten ssh ...` | Kitty переносит terminfo и настраивает интеграцию в домашнем каталоге удалённого пользователя |

Пустой или отсутствующий список означает совместимый режим для всех хостов. Список находится **только локально**: `~/.config/terminal-dotfiles/managed-ssh-hosts`. По одной точной записи `user@hostname:port` на строку, без масок и доменных суффиксов. Функция получает значения через `ssh -G`, поэтому учитываются `HostName`, `User`, `Port` и параметры командной строки. Несколько SSH-алиасов с одинаковым конечным назначением используют одну запись. Проверка SSH host key остаётся у OpenSSH.

Пример содержимого приватного файла:

```text
alice@dev.example.net:22
```

Получить запись для уже настроенного SSH-алиаса можно без подключения к серверу:

```sh
ssh -G my-alias | awk '
  $1 == "user" { u = $2 }
  $1 == "hostname" { h = $2 }
  $1 == "port" { p = $2 }
  END { print u "@" h ":" p }
'
```

## Когда считать хост управляемым

Добавляйте запись только если одновременно выполнены эти условия:

1. У вас есть разрешение на изменения в домашнем каталоге удалённого пользователя при каждом подключении через `kitten ssh`.
2. Хосту нужен полный режим Kitty; на нём можно хранить terminfo и файлы интеграции Kitty. Для команд через `sudo` terminfo также должен быть доступен привилегированному пользователю, например через системный пакет `kitty-terminfo`.
3. Если нужен одинаковый prompt, Starship и общий `starship.toml` уже установлены и подключены к используемой на хосте оболочке. Наличие terminfo само по себе prompt не меняет.

Версия ОС, суффикс DNS и доступность `sudo` **не** означают управляемость. Новые хосты никогда не добавляются автоматически. Текущее состояние terminfo можно проверить без изменений на сервере командой `infocmp xterm-kitty`; оно не заменяет разрешение на работу `kitten ssh`.

Пока изменения на серверах не разрешены, оставьте список пустым. Уже установленный terminfo на отдельном сервере не делает его управляемым автоматически.

## Использование и обход

После добавления нового файла из пакета `zsh` на уже настроенном устройстве один раз повторите из корня репозитория:

```sh
stow --no-folding --simulate --verbose --target="$HOME" zsh
stow --no-folding --target="$HOME" zsh
```

Затем откройте новую вкладку Kitty. `ssh my-alias` выберет режим по приватному списку. Для разового обычного OpenSSH вызовите `command ssh my-alias`; для разового полного режима на разрешённом хосте — `kitten ssh my-alias` (если `kitten` доступен в `PATH`) или полный путь к `kitten`. Вне Kitty функция передаёт вызов обычному `ssh`.

Для диагностики на удалённом хосте: `printf '%s\n' "$TERM"`, `infocmp "$TERM"` и `tput colors`. Сообщение об отсутствии `editor` проверяйте отдельно: PowerDNS использует переменную `EDITOR`, а при её отсутствии запускает `editor`. Настройка `TERM` не устанавливает Starship и не определяет редактор.

Официальные источники: [Kitty SSH kitten](https://sw.kovidgoyal.net/kitty/kittens/ssh/), [Kitty FAQ о terminfo и `sudo`](https://sw.kovidgoyal.net/kitty/faq/), [OpenSSH `ssh -G`](https://man.openbsd.org/ssh), [PowerDNS `pdnsutil`](https://doc.powerdns.com/authoritative/manpages/pdnsutil.1.html).
