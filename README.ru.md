# Terminal dotfiles

[English](README.md) · **Русский**

[Установка](#установка-с-чистого-устройства) · [Миграция Ubuntu](#миграция-на-настроенной-ubuntu-2404) · [Сетевая панель Kitty](#сетевая-панель-kitty) · [Локальные переопределения](#локальные-переопределения)

Общая конфигурация Kitty, zsh, Bash, Starship и zoxide для macOS, Ubuntu 24.04 GNOME, Ubuntu 24.04 KDE Plasma и Debian 13 KDE Plasma. Цель — одинаковые prompt, цвета, шрифт и сочетания клавиш внутри терминала на разных устройствах.

## Состав

| Пакет Stow | Файл в домашнем каталоге | Назначение |
| --- | --- | --- |
| `zsh` | `~/.zshrc`, `~/.config/terminal-dotfiles/ssh.zsh` | completion, zoxide, Starship, совместимый SSH и два необязательных локальных файла |
| `bash` | `~/.bashrc` | Starship, zoxide и совместимый SSH для интерактивного Bash, приватные настройки в `~/.bashrc.local` |
| `kitty` | `~/.config/kitty/kitty.conf`, `~/.config/kitty/tab_bar.py` | внешний вид, вкладки, окна и сочетания `Command`/`Super` |
| `starship` | `~/.config/starship.toml` | общий prompt |

zoxide использует стандартные команды `z` и `zi`; для интерактивной команды `zi` устанавливается fzf. База посещённых каталогов создаётся на каждом устройстве отдельно. Oh My Zsh, Powerlevel10k и autojump не нужны.

## Установка с чистого устройства

Сначала выполните инструкцию для [macOS](docs/macos.md), [Ubuntu GNOME](docs/ubuntu-24.04-gnome.md), [Ubuntu KDE](docs/ubuntu-24.04-kde.md) или [Debian KDE](docs/debian-13-kde.md). Она устанавливает Git, Stow, Kitty, Starship, zoxide, fzf, плагины zsh и шрифт. Затем на том же устройстве выполните:

```sh
mkdir -p "$HOME/work/github.com/levonti"
git clone https://github.com/levonti/terminal-dotfiles.git "$HOME/work/github.com/levonti/terminal-dotfiles"
cd "$HOME/work/github.com/levonti/terminal-dotfiles"
stow --no-folding --simulate --verbose --target="$HOME" zsh kitty starship &&
  stow --no-folding --target="$HOME" zsh kitty starship &&
  sh scripts/install-bash.sh
```

На чистом устройстве базовый Stow создаст пять ссылок, а Bash-установщик — шестую. Если конфиги уже существуют, воспользуйтесь [режимом миграции](#миграция-на-настроенной-ubuntu-2404).

`--no-folding` оставляет каталоги в `$HOME` обычными каталогами: рядом с общими ссылками можно хранить приватные файлы. [Руководство GNU Stow](https://www.gnu.org/software/stow/manual/stow.html).

После установки запустите `zsh -l` и проверьте `starship --version`, `zoxide --version`, `fzf --version`, `type z` и `type zi`. Затем запустите `bash`: в нём должны быть метка `bash`, команды `z` и `zi`; вернитесь командой `exit`. Проверьте версию Kitty по платформенной инструкции. Если shell по умолчанию ещё не zsh, выполните шаг смены shell в инструкции платформы и войдите в систему заново.

### Обновление настроек

В клоне при необходимости переключитесь на `main` командой `git switch main`. Если `main` отслеживает `origin/main`, выполните `git pull`. На Ubuntu нажмите `Ctrl+Shift+F5` в Kitty, чтобы перечитать конфиг.

Существующие ссылки Stow подхватят изменения в подключённых файлах. Если в репозитории появились новые файлы или пакеты, запустите Stow ещё раз.

## Миграция на настроенной Ubuntu 24.04

Если Stow ещё отсутствует, установите его командой `sudo apt install stow`. Посмотрите план из корня клона.

```sh
sh scripts/install.sh --check
```

Проверка перечисляет файлы для переноса, новые ссылки и уже подключённые конфиги. Скрипт останавливается, если целевой путь занят чужой или битой ссылкой, каталогом вместо файла либо если родительский каталог сам является ссылкой. Для каждого изменяемого пути проверяются права записи и доступа в ближайшем существующем родительском каталоге.

Миграция рассчитана на `~/.zshrc` и `~/.config/kitty`. Если `ZDOTDIR` или `KITTY_CONFIG_DIRECTORY` указывает в другое место либо Kitty находит другой `kitty.conf` через `XDG_CONFIG_HOME`, скрипт покажет оба пути и остановится. Запускайте скрипт с тем же окружением, что и Zsh и Kitty. Если `ZDOTDIR` задан только внутри Zsh, экспортируйте его перед проверкой. Если Kitty запускается с флагом `--config`, сверяйте указанный там путь с `~/.config/kitty/kitty.conf`. Для Starship допустимо локальное переопределение через `STARSHIP_CONFIG`.

После успешной проверки запустите миграцию.

```sh
sh scripts/install.sh --migrate
```

Скрипт повторяет проверку и переносит конфликтующие файлы Zsh, Kitty и Starship в новый приватный каталог `~/.terminal-dotfiles-backup.*`, сохраняя относительные пути. Если есть обычный файл `~/.zshrc.zwc`, скрипт также переносит его в бэкап, чтобы Zsh загрузил общий `.zshrc`. Затем скрипт запускает пробный и рабочий проходы Stow с собственными параметрами и проверяет все пять ссылок. При ошибке он удаляет созданные за этот запуск ссылки и возвращает оригиналы, включая `.zshrc.zwc`. Если восстановить файл не удалось, он остаётся в каталоге бэкапа, путь к которому скрипт выводит. Повторный успешный запуск сохраняет существующие ссылки и бэкапы.

Сравните сохранённые конфиги с общими и перенесите нужные строки в [локальные переопределения](docs/local-overrides.md). Уже существующие локальные файлы сохраняются. Bash по-прежнему подключается отдельной командой `sh scripts/install-bash.sh`.

## Bash на macOS и Linux

Установщик `scripts/install-bash.sh` подключает один и тот же пакет Bash на macOS, Ubuntu и Debian. Если обычный `~/.bashrc` уже есть, он переносит его в `~/.bashrc.local`, а затем создаёт ссылку на общий конфиг. Приватный файл читается до инициализации zoxide и Starship. При наличии одновременно обычного `~/.bashrc` и `~/.bashrc.local` установщик останавливается. Повторный запуск при уже установленной ссылке безопасен.

Предупреждение о симуляции в первом проходе Stow ожидаемо. Установщик сообщает об успехе после проверки ссылки `~/.bashrc`. Если `.stowrc` включает симуляцию и ссылка так и не появилась, установщик вернёт исходный `.bashrc` и завершится с ошибкой.

После переноса проверьте `~/.bashrc.local`: если в нём уже запускались Starship или zoxide, уберите дублирующую инициализацию. Интерактивный Bash без входа в систему читает `~/.bashrc`; для Bash с `--login` существующий `~/.bash_profile` должен также подключать `~/.bashrc` при необходимости. [Правила запуска Bash](https://www.gnu.org/software/bash/manual/html_node/Bash-Startup-Files.html).

Левая часть prompt, включая метку оболочки, общая. Правая часть `right_format` в Bash требует Ble.sh версии 0.4 или новее и без него не отображается. [Документация Starship](https://starship.rs/advanced-config/#enable-right-prompt).

## Локальные переопределения

Общий `.zshrc` сначала добавляет стандартные каталоги пользовательских бинарников и Homebrew в `PATH`, затем читает `~/.zshrc.local` перед инициализацией инструментов и `~/.zshrc.local.post` после основных настроек. Общий `.bashrc` читает `~/.bashrc.local` перед zoxide и Starship. Kitty в конце читает необязательный `~/.config/kitty/kitty.local.conf`. Для Starship возможна полная локальная замена через `STARSHIP_CONFIG`. Подробности: [локальные переопределения](docs/local-overrides.md).

## Kubernetes в zsh

Опциональный Kubie изолирует контекст и namespace между вкладками. Starship и Kitty показывают цветную метку окружения и отдельную категорию (LAB, LOCAL, CORP или PUBLIC). Общий resolver определяет категорию по каталогу исходного kubeconfig, а для окружения также учитывает точные исключения. Имена контекстов произвольны. Требуется отдельная установка runtime через `sh scripts/setup-kube-environment.sh`. [Установка и диагностика](docs/kubie.md).


## Вкладки Kitty

Плоская панель с зазорами, контрастной активной вкладкой, номерами и компактными названиями. `Command/Super+1…9` переключает вкладки по номеру, `Command/Super+P` открывает список, `Command/Super+Shift+T` задаёт имя сессии. Подписи сохраняют каталог при запуске программы (`project htop`) и добавляют сообщённые сервером хост и команду для SSH. При нехватке места во вкладке Kubie приоритет у окружения и категории кластера. Starship отделяет контекст от ввода команды и показывает Git-статус со счётчиками. [Оценка всего окна и варианты prompt](docs/appearance.md), [настройки вкладок](docs/kitty-tabs.md).

На Ubuntu используйте `Ctrl+Shift+1…9` для перехода по номеру вкладки и `Ctrl+Shift+Left/Right` для перехода к соседней вкладке. Сочетания с цифрами заменяют стандартное переключение панелей по номерам. [Ubuntu GNOME](docs/ubuntu-24.04-gnome.md) · [Ubuntu KDE](docs/ubuntu-24.04-kde.md).

### Сетевая панель Kitty

На Ubuntu 24.04 панель показывает входящий и исходящий трафик компьютера даже при одной вкладке. Установите последний стабильный релиз Kitty официальным установщиком. В пакете `apt` для Ubuntu 24.04 (Kitty 0.32.2) отсутствует API панели. Если Stow уже подключил `kitty.conf` и `tab_bar.py`, для обновления этих файлов достаточно обновить клон. [Установка и ярлык для Linux](docs/linux-install.md#3-zoxide-fzf-starship-и-kitty).

```sh
installer_file=$(mktemp) &&
  curl -fsSL https://sw.kovidgoyal.net/kitty/installer.sh -o "$installer_file" &&
  sh "$installer_file" launch=n &&
  rm -f "$installer_file" &&
  "$HOME/.local/kitty.app/bin/kitty" --version
```

Запустите новую версию командой `"$HOME/.local/kitty.app/bin/kitty"`. В широком окне Kitty справа вверху появятся `Linux`, `↓` и `↑`.

Чтобы включить панель на этом устройстве даже при одной вкладке, выполните команду.

```sh
printf '%s\n' 'tab_bar_style custom' 'tab_bar_min_tabs 1' > "$HOME/.config/kitty/terminal-dotfiles-network.conf"
```

Чтобы выключить сетевую панель и показывать обычную панель при двух и более вкладках, выполните команду.

```sh
printf '%s\n' 'tab_bar_style fade' 'tab_bar_min_tabs 2' > "$HOME/.config/kitty/terminal-dotfiles-network.conf"
```

Перечитайте конфиг через `Ctrl+Shift+F5` на Linux или `Ctrl+Command+,` на macOS. Эти команды меняют только отдельный файл, который Kitty читает после `kitty.local.conf`. Чтобы вернуться к настройкам из остальных конфигов, выполните `rm -f "$HOME/.config/kitty/terminal-dotfiles-network.conf"`. [Как работает сетевая панель](docs/network-panel.md).

## SSH из Kitty

Обычная команда `ssh` в интерактивных Zsh и Bash автоматически использует `TERM=xterm-256color` для всех хостов. При последовательных SSH-подключениях этот тип терминала передаётся дальше, если промежуточный хост его не переопределяет. Локальный Kitty сохраняет свой `TERM`; маски управляемых хостов больше не используются. Подробности и проверка описаны в [руководстве по SSH](docs/ssh.md).

Приватные файлы, историю shell, базу zoxide, ключи и токены не добавляйте в публичный репозиторий. Файлы в `examples/` содержат только безопасные образцы.

## Проверка совместимости

[Версии](docs/versions.md) фиксируют проверенную конфигурацию Mac и версии, используемые инструкцией чистой установки. Linux пока не проверялся на самих целевых устройствах. На GNOME и KDE глобальные сочетания `Super` могут перехватываться до Kitty; соответствующие настройки среды описаны в инструкциях по платформам. [Сочетания Kitty](docs/keybindings.md).
